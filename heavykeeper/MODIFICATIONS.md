# Local Modifications to heavykeeper

Changes applied to the vendored `heavykeeper` crate, in the order they were
committed on top of the upstream `main` import. Each row explains what the
change does and why we want it. Commit links point at
`detemmienation/valkey-bloom`.

Baseline: [Integrate heavykeeper-rs as a local path dependency](https://github.com/detemmienation/valkey-bloom/commit/12580474d60d9729dc96859010b99684d723f8fe)
vendors upstream `main` (default `u64` cells) so we can modify it in-tree.

| # | Change | Why | Notes / follow-up | Commit |
|---|--------|-----|-------------------|--------|
| 2 | Defrag support | Relocate the sketch's heap allocations through Valkey's defrag allocator via a safe `Reallocator` trait. | — | [4756214](https://github.com/detemmienation/valkey-bloom/commit/4756214193aab515a87c37c8075f7bf3ec30241c) |
| 3 | Generic `Fingerprint`/`Counter` types | Make cell fingerprint and counter widths generic (`F`/`C`), defaulting to `u64`. Enables narrower cells without forking the type. | Optional precision: `CuckooTopK<Vec<u8>>` stays `u64`; switching widths is just the type alias. | [27b90f7](https://github.com/detemmienation/valkey-bloom/commit/27b90f72de910ecd86147a2f48cc5d63493cdc12) |
| 4 | `u32` fingerprint + counter | Instantiate the TopK sketch as `CuckooTopK<Vec<u8>, u32, u32>`, halving per-cell memory from 16 to 8 bytes. | Smaller chance someone needs `u64`. Consider exposing width as a config/command argument. Evaluate whether Valkey's counter (or other TopK counters) need `u32` vs `u64`. | [c96a1cc](https://github.com/detemmienation/valkey-bloom/commit/c96a1cc67492cd49c1b5b1144a385c3b73477f01) |
| 5 | Single-copy priority queue + drop free-slot list | Store each tracked item once (`hashbrown::HashTable<u32>` maps to a slot index instead of duplicating the key), halving per-item memory in the PQ. A full queue now replaces the min slot in place instead of deleting and reusing slots, so the `free_slots` list is no longer needed and is removed. | Item stored once instead of twice; no free-slot. | [5a85b9c](https://github.com/detemmienation/valkey-bloom/commit/5a85b9c63d9069b0694139f61e410f222d48ca8b) |
| 7 | Remove decay-threshold lookup table | Drop the 1024-entry `u64` precomputed table; compute `decay^count` directly with `powf`. Saves the table's memory (~8 KB/sketch). | Kept because it most benefits small `k`. Trade-off: a `powf` per lobby-decay check instead of an O(1) table lookup. | [97a0735](https://github.com/detemmienation/valkey-bloom/commit/97a07356cd99eb3b34d937270fa4afd2ab389968) |
| 8 | Self-describing cell widths in serialization | Record `size_of::<F>()`/`size_of::<C>()` in the cuckoo payload and validate them on load (`CellWidthMismatch`). Folded into the initial format version (nothing released yet). A stream written by one width instantiation now fails loudly instead of misparsing when read by another (e.g. after the u64 to u32 switch in #4). | Hardening follow-up to #3/#4. | local |
| 10 | Hoist decay threshold out of the per-unit loop | `decay_threshold()` (a `powf`) is recomputed only when the cell count changes instead of once per unit of increment, so a large `TOPK.INCRBY` no longer pays one `powf` per unit on the main thread. | Hardening follow-up to #7. | local |
| 11 | PQ robustness: `allocation_size()` | `mem_bytes` uses hashbrown's own `allocation_size()` instead of hand-rolled bucket math that could drift across hashbrown upgrades. | Hardening follow-up to #5. | local |
| 12 | Replace `ahash` with seeded SipHash-1-3 (`SipState`) | `ahash` output varies by CPU architecture, feature set, and crate version, so serialized sketches could only be restored on the platform that wrote them (the hasher probe failed the load otherwise). SipHash-1-3 is a frozen spec: identical output everywhere, so RDBs are portable across x86_64/aarch64 and crate upgrades, matching the bloom side's portability (the `bloomfilter` crate already uses SipHash keys). Keys derived from the sketch seed via splitmix64; keyed hashing retains DoS resistance. `ahash` dependency removed. | Folded into the initial format version (nothing released yet). Cross-platform pin test added in `sip.rs`. | local |
| 13 | Layout-derived up-front size estimate | Add `CuckooTopK::estimated_mem_bytes()` and `TopKQueue::entry_mem_bytes()` so the module's `TOPK.RESERVE` size check derives per-cell and per-entry costs from the real types instead of hardcoded constants (8 bytes/cell, 128 bytes/entry) that silently drift if the cell width or slot layout changes. Test pins the estimate as an upper bound of actual structural `mem_bytes`. | Companion to the module-side `estimated_size()` rewrite. | local |
| 14 | Rebuild the PQ lookup table when tombstones grow it | hashbrown leaves a tombstone on `remove` and, once tombstones exhaust the growth budget, doubles the allocation instead of rehashing in place, even though live entries never exceed `k`. | Found by the end-to-end perf run under concurrent INCRBY; regression test | local |
| 15 | `FromBorrowed` key trait; generic PQ counter width | Replace the `Q: ToOwned<Owned = T>` bound on `CuckooTopK::add` (and the one `to_owned()` call behind it) with a crate `FromBorrowed<Q>` trait so the stored key type is no longer pinned to `Vec<u8>` for `[u8]` lookups; the module now stores `Box<[u8]>` (16-byte fat pointer, no capacity word, 8 bytes per slot saved). `TopKQueue<T, C: Counter = u64>` stores the slot count at the cell width `C` instead of a fixed `u64` (saturating on the way in; the API still speaks `u64`), since a `u32`-cell sketch can never hand the queue a count above `u32::MAX`. Serialization is generic over `AsRef<[u8]> + FromBorrowed<[u8]>`; the wire format is unchanged and `Vec<u8>` bytes restore into `Box<[u8]>` sketches (pinned by test). | Memory: `Slot<Box<[u8]>, u32>` is 32 bytes vs 40 for `Slot<Vec<u8>, u64>`. Read-only lookups (`count`, `contains`, `contains_top_k`) drop the `ToOwned` bound entirely. `TopK`/`BucketedTopK` untouched (module does not use them). | local |
| 16 | `SmallKey`: 16-byte key with 15 inline bytes | New `small_key.rs`. A 16-byte owned byte string (same size as `Box<[u8]>`) that stores keys of up to 15 bytes directly in the slot and spills longer ones to a heap allocation. Byte 15 is the discriminant (inline `len` 0..=15, or 0xFF for heap). Implements `Borrow<[u8]>`, `AsRef<[u8]>`, `Hash` (identical to `[u8]`, so `&[u8]` probes find it in the lookup table), `Ord`, `Clone`, `FromBorrowed<[u8]>`. The module's `Sketch` is now `CuckooTopK<SmallKey, u32, u32>`; `memory_usage`/the gauge charge `heap_bytes()` (0 for inline keys). | Removes one heap allocation per tracked item for short keys (IDs, IPv4 strings, tokens) and the allocator rounding that came with it; the linear compare no longer chases a pointer. Long keys cost exactly what `Box<[u8]>` did. The type carries a small, self-contained `unsafe` union; no Miri/Valgrind on the dev host, so it is covered by tests only. Slot stays 32 bytes. | local |
| 17 | One bucket-major cell array; trim per-key duplication | `lobbies` and `heavy` were two `Box<[Cell]>` allocations; they are now one `cells` array laid out bucket-major (lobby cell, then `depth` heavy slots, per bucket). For the default depth 7 a bucket is exactly one 64-byte cache line, so the lobby read and the heavy-slot scan for a bucket hit the same line. Wire format unchanged: `to_bytes` still writes lobbies then heavy (via `lobby_cells()`/`heavy_cells()` iterators) and `from_bytes` interleaves on load; golden-bytes test unchanged. Also drops the `+1` on the PQ heap index capacity (the heap never holds more than `k`), and the module's `TopKObject` no longer duplicates k/width/depth/decay that the sketch already stores (getters delegate). | Saves 44 bytes per key as reported by `TOPK.INFO SIZE` (16 Box header + 4 heap slot + 24 wrapper fields) | local |
